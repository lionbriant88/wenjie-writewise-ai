# 质量修复与免费教师试用准备

本轮在 `codex/ai-pipeline-optimization` 工作树修复 9 月 6 日真实验收发现的问题；尚未合并主工作区或部署公网。当前主流程继续使用 Kimi K3 直接多模态，一次请求完成识别和批改，外部 v2 合同不变。

## 修复范围

| 问题 | 修复及边界 |
| --- | --- |
| “应用文”等分类标签混入正文 | 明确区分分类标签、题目指令和真正作文标题；内部逐页检查列出非正文标签。如声明已排除的标签仍作为整行出现在正文，生成教师核对提示，不按首行或中文一律删除。 |
| 正文在图片边缘被截断却无提醒 | 同一次模型请求逐页检查正文完整性；将裁切判定转换为固定补拍提醒，不根据题目补写看不见的文字，也不将裁切算作学生字迹扣分。 |
| 可合理辨为正确的字迹仍被扣分 | 增加内部结构化字迹判定和逐项扣分数额。只在条目与原扣分归属可验证时重建卷面分，未知、非法、缺关联或证据错位继续复核。依据已辨清正文成立的独立语法/用词问题仍保留，不能用字迹静默误删语言纠正。内部字段不进入教师端 v2 字迹结构。 |
| 扣分、引用和总分说明不一致 | 收紧扣分依据和现有问题关联，向模型明确整数总分与真实字迹扣分的现有上限规则；保留真实的 `partial` 和复核提示。 |
| PDF 转换期间继续拍照/上传产生容量竞态 | 异步返回按最新卡片状态校验 10 页上限和页序；删除卡片或卸载页面后丢弃迟到结果，不创建无主预览 URL。 |

Provider 内部 Schema 升为 `essay-grading-provider-v3`，缓存和逐篇幂等身份随版本改变。网页、Gateway 和未来小程序对外仍使用 `multimodal-grading-request-v2`、`grading-result-v2` 与 `POST /grading/grade-images`。未引入 OCR、图片压缩或额外模型复核。

结构化字段可以检查模型声明与计分的一致性，不能独立证明视觉识别正确。真实图片的裁切与分类标签仍由模型判断，不能保证零漏报。Kimi K3 的 temperature 固定为 1.0，不能以调成 0 来保证每次评分完全一致；本轮不改这些供应商参数。[Kimi 官方参数](https://platform.kimi.com/docs/api/models-overview)

## 摄像头测试覆盖

此前 18 篇真实验收使用已有图片文件，**没有实际调用摄像头**。本轮新增的是文件层自动化测试：拍照入口返回的 File 是否进入正确学生卡片、同一文件可再次选择、页序与原文件是否保留，以及和 PDF 并发追加时的上限。

现有“拍照上传”通过 `input type="file" capture="environment"` 请求设备拍摄入口；没有实现 `getUserMedia` 实时视频预览。在手机上是否直接打开相机由浏览器决定，电脑上可能只打开文件选择器。因此真实摄像头权限、拒绝后重试、取消、前后摄、横竖屏与照片方向，以及 iOS Safari / Android 浏览器 / 微信内置浏览器，都仍需真机验证。不能把文件测试写成摄像头实机验收通过。

## 建议先做邀请制网页版

建议先邀请 5–10 位教师试用，手机和电脑共用一个自适应网页。先验证教师连续使用是否顺畅，再做独立微信小程序。小程序和收费系统不是免费试用的前置条件；下列可靠性与数据保护能力仍须完成。

| 优先事项 | 最小实施内容 | 交付时要实际验证 |
| --- | --- | --- |
| 教师账号与数据隔离 | 管理员创建受邀账号；服务端对每个任务、图片、结果验证教师归属 | 教师 A 不能通过修改 ID 访问教师 B 的任务或图片 |
| 保存与恢复 | 持久保存任务、评分标准、图片页序、结果版本和教师修改 | 刷新、退出重登、换设备后仍可继续；原图与结果不丢失 |
| 后台任务与防重复计费 | 服务端维护任务队列、持久幂等记录、调用状态与未知结果；保持有界并发 | 断网重连、重复点击、进程重启不盲目新增计费调用；单篇失败不阻断其他作文 |
| 免费额度与资源保护 | 每位教师及全局额度、每日/每月 API 预算、并发限制、暂停开关；覆盖生成标准与重批 | 用完额度确实停止新调用；未知调用继续占用预算 |
| 可运行的部署 | HTTPS、仅服务端持有 Key、私有图片访问、进程自动恢复、错误告警与异地备份 | 从备份实际恢复一次；图片链接不能绕过教师权限 |
| 真实使用验收 | 手机拍照、PDF、多页、教师改文重批、结果确认、恢复路径；清除未接真实数据的演示入口 | 受邀教师在自己的设备上完整完成一次真实任务 |

现有 React 内存任务和单进程内存 registry 只能支撑本地原型。服务器租好后直接启动当前程序，仍然无法解决刷新丢数据、多人隔离和重启后的重复计费风险。

试用版可以先用一个应用实例加一个数据库，配私有文件存储；数据库可同机起步，但备份应在另一处。不需要在试用开始前引入集群、复杂组织管理、短信注册、支付订单或独立 Redis。具体服务器配置应根据最终后台方案、并发数与上传大小确定。

## 需要你准备的内容

1. **试用负责人和名单**：首批教师人数、每人每天大约批改多少篇、由谁收集问题。
2. **云服务账号与域名**：云账号由你持有；确定网站运营主体和部署区域，再选服务器、域名和私有存储。
3. **运行预算**：免费给教师使用仍有服务器、存储和 Kimi 消耗；明确每月总预算与每人额度。此前单篇初批平均约 0.43 元只是这 18 篇的观察，不是任何篇幅的固定价格。
4. **数据使用规则**：确认作文使用授权、是否包含学生姓名、保留多久、如何删除；默认使用学生编号，说明作文图片将发送给 Kimi 处理。
5. **真机测试设备**：至少覆盖一台 iPhone、一台常用 Android 手机及教师日常使用的浏览器/微信入口。

免费服务也要按实际服务和部署情况办理相应手续。在中国境内提供非经营性互联网信息服务仍有备案要求，ICP备案可通过接入商办理；教育类服务的具体备案类别和前置条件应在购买部署资源前向接入商与所在地通信管理部门核实。[工信部备案办法](https://www.miit.gov.cn/gyhxxhb/jgsj/cyzcyfgs/bmgz/xxtxl/art/2024/art_84a0cfa0ebd049bbbe751dca9a008e56.html)

处理学生个人信息需明确告知和适用处理依据；涉及不满 14 周岁的个人信息，还需监护人同意及专门处理规则。可以先用匿名作文试用，减少无关个人信息的收集。[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

推荐实施顺序：教师账号与持久化 → 后台队列及用量保护 → 私有部署与恢复测试 → 手机拍照和小范围真实试用 → 根据反馈决定小程序与收费。
