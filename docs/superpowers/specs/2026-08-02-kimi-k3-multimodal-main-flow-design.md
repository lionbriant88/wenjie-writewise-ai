# Kimi K3 多模态主流程与创建任务精简设计

## 状态

- 日期：2026-08-02
- 状态：用户已批准
- 范围：创建任务界面精简；OCR 退出主流程；Kimi K3 统一完成图片理解、评分标准生成与作文批改；完成自动化和类人工全流程验证

## 目标

本轮只解决两个产品问题：

1. 创建任务时不再要求教师预先区分应用文、读后续写或具体题型，只处理原材料、满分以及经教师确认的评分标准。
2. 学生作文图片不再先经过 OCR 再交给文本模型。Kimi K3 直接理解图片，在一次批改请求中返回忠实转写和评分结果，并尽量区分手写正文与试卷上的印刷提示。

实现完成后，使用合成材料完成自动化测试和真实 Kimi 的类人工端到端验证；真实手写作文与真实写作材料由用户后续提供并另行验收。

## 非目标

- 不重做上传分组、页序调整、进度、结果、教师确认或班级统计页面。
- 不改变评分标准采用百分比权重的现有产品约定。
- 不在本轮决定是否永久删除 OCR Gateway；只让它退出主流程。
- 不增加前端模型选择器。
- 不扩展 PDF、Word 或其他需要额外转换的材料格式。
- 不进行与本次主流程无关的重构。

## 方案选择

采用“扩展现有 Grading Gateway”的渐进方案：

- Grading Gateway 新增 Kimi K3 多模态 Provider，并承担原材料理解、评分标准生成、作文图片理解和批改。
- 前端继续通过本地 Gateway 调用模型，浏览器永远不接触 API key。
- OCR Gateway 代码暂时保留，但新任务主流程不再调用它。
- DeepSeek 不再作为运行时 Provider；删除本地配置与示例配置中的 DeepSeek 环境变量。旧实现本轮不做额外清理，以避免扩大改动范围。

相较于“Kimi 转写、DeepSeek 批改”的双模型方案，此方案保留完整图像语境、减少一次模型边界和重复调用。相较于重建全新 AI Gateway，此方案能复用现有的结果归一化、错误映射和教师确认机制。

## 创建任务界面

创建任务页收敛为单页主流程：

1. 上传一张或多张原材料图片。
2. 调整材料图片顺序或删除错误图片。
3. 输入满分。
4. 点击“生成评分标准”。
5. 查看并编辑 Kimi 生成的任务名称、材料摘要、写作要求、评分标准和风险提示。
6. 点击“确认并创建任务”。

页面删除以下字段和分支：

- 应用文 / 读后续写选择；
- 具体题型选择；
- 与文体绑定的固定评分模板选择；
- 班级选择；
- 是否生成班级讲评选项。

任务名称根据材料内容自动生成。班级仍在后续上传作文环节选择。除创建任务页及进入批改所必需的交互外，不重新设计其他页面。

## 评分标准生成与确认

评分标准继续使用百分比权重。每个评分维度包含：

- 稳定标识、名称和百分比权重；
- 达标要求；
- 扣分关注点；
- 来自材料的生成依据；
- 需要教师确认的歧义或风险。

所有维度权重必须恰好合计 100%。批改时依据任务满分换算每个维度的最高分。确定性校验负责检查满分、必填字段、维度标识唯一性和权重总和，不声称验证主观评分标准的语义正确性。

为提高评分标准可靠性，点击一次“生成评分标准”后由 Gateway 完成两个受控阶段：

1. Kimi K3 从原材料图片提取任务要求并生成评分标准草案。
2. Kimi K3 以复核角色重新查看原材料与草案，检查材料覆盖、无依据内容、维度冲突和权重问题，返回通过后的修正版或明确风险。

两个阶段都使用严格结构化输出。复核未通过或确定性校验失败时不创建半成品任务，只保留材料和满分供教师重试。最终评分标准必须由教师明确确认。

## 多模态作文批改

上传、作文分组和页序调整继续使用现有交互。完成分组后，前端直接把每篇作文的有序图片和已确认任务包发送给 Grading Gateway，不再调用 OCR Gateway，也不再显示“确认 OCR 文本”作为进入批改的前置步骤。

每篇作文由 Kimi K3 在一次请求中完成：

- 识别并按页序转写学生手写正文；
- 排除试卷印刷提示、题干、页眉页脚和非作文标记；
- 返回无法可靠区分的区域或转写风险；
- 依据已确认评分标准生成分项评分、总分、问题定位、修改建议和总评。

Kimi 返回的转写和评分结果被适配到现有结果状态模型，因此进度页、结果页、教师编辑、教师确认和班级统计尽量保持原样。作文仍逐篇处理；单篇失败不阻断其他作文。

教师在结果页同时核对原图、转写和批改。模型无法可靠区分手写与印刷内容、问题证据无法在转写中定位或响应不完整时，结果进入“需要教师复核”，而不是伪装为可靠结果。教师修改转写后，基于旧转写的评分立即失效，必须显式重新批改后才能确认。

## 接口与文件传输

前端与 Gateway 使用 `multipart/form-data` 传输本地图片，复用现有图片上传约束和实现模式：

- 支持 JPG、PNG、WebP；
- 单张图片最大 8 MB；
- 单次请求最多 10 页；
- Gateway 校验 MIME、数量和大小后，在内存中转换为 Kimi 所需的 Base64 图片输入；
- 不把本地路径、图片二进制或 Base64 内容写入日志。

Grading Gateway 提供两个职责清晰的入口：

- 评分标准入口：材料图片 + 满分，返回自动任务名称、结构化任务要求、百分比评分标准和风险提示；
- 作文批改入口：已确认任务包 + 有序作文图片，返回转写与现有批改结果契约兼容的结构化结果。

旧的文本批改契约只作为已有代码和测试的兼容边界，不再由新页面生成。

## Kimi 配置

本地 `grading-gateway/.env` 使用：

```dotenv
GRADING_PROVIDER=kimi
KIMI_API_BASE=https://api.moonshot.ai/v1
KIMI_MODEL=kimi-k3
KIMI_REASONING_EFFORT=high
KIMI_MAX_COMPLETION_TOKENS=8192
KIMI_API_KEY=
```

仓库中的 `.env.example` 只能保留空 key 和非敏感默认值。`KIMI_API_KEY` 不得进入前端、日志、测试 fixture、文档或 Git。所有 `DEEPSEEK_*` 环境变量从本地配置和示例配置中删除，DeepSeek 不再注册为可选运行时 Provider。

Kimi K3 请求遵循当前官方能力边界：图片以内嵌 Base64 内容发送，结果使用严格 JSON Schema，业务只解析最终 `message.content`，不解析思考内容。固定或不受支持的采样参数不发送。

## 错误处理

Gateway 将上游错误转换为稳定、安全的本地错误：

- key 缺失或 Provider 未配置；
- 鉴权失败；
- 账户余额或资源不可用；
- 限流；
- 超时或网络不可用；
- 图片类型、数量或大小不合法；
- 内容过滤；
- 空响应、非 JSON、结构不完整或 JSON Schema 不匹配。

错误响应只包含请求标识、安全错误码、用户可理解的提示和是否可重试，不包含密钥、图片内容、作文正文、上游原始响应或堆栈。

评分标准失败时保留创建页输入并允许重试。作文批改失败时只影响当前作文，允许单独重试或转人工处理。系统不进行可能产生重复费用的静默自动重试。

## OCR 与 DeepSeek 边界

- 新主流程在 OCR Gateway 关闭时必须完整通过。
- OCR Gateway 的代码、测试和启动能力暂时保留，是否永久删除由用户后续决定。
- 页面不再展示 OCR Provider、OCR 进度或 OCR 确认作为新任务的必经步骤。
- DeepSeek 环境变量和运行时注册被移除。
- DeepSeek Provider 旧实现可以暂时留在代码库中，但新入口、默认配置和类人工验证不得调用它。

## 自动化验证

实现遵循测试先行。新增或调整的测试至少覆盖：

- 创建任务页不再出现文体、题型和旧评分模板；
- 原材料图片、满分、生成、编辑和确认评分标准流程；
- 百分比权重合计 100% 的确定性校验；
- Kimi 请求中的多页图片顺序、严格结构化输出和模型参数；
- Kimi 鉴权、余额、限流、超时、无效响应和图片限制的安全映射；
- 印刷提示被排除、无法区分时触发教师复核；
- 逐篇批改与单篇失败隔离；
- 编辑转写后评分失效；
- OCR Gateway 不可用时主流程仍能通过；
- DeepSeek 不再被运行时选择或配置。

全部前端、Grading Gateway 和 OCR Gateway 的相关测试、类型检查、静态检查及前端构建必须通过。OCR 测试继续运行是为了确认保留代码没有被本轮改动破坏，不代表 OCR 仍在主流程中。

## 类人工端到端验证

在真实学生材料到来前，创建不含身份信息的合成夹具：

- 一组写作原材料图片；
- 至少一篇多页合成作文图片；
- 作文图片包含与正文并存的印刷题干或提示，用来验证 Kimi 是否排除非手写内容；
- 一个受控失败场景，用于验证安全错误和单篇恢复。

真实 Kimi 验证默认控制在四次成功上游调用以内：评分标准生成、评分标准复核和两篇作文批改。只有环境性失败且确认不会造成重复成功计费时才人工重试。最终报告记录调用次数、通过/失败、状态流转和安全错误码，不记录材料正文、图片、上游原始响应、账户信息或密钥。

浏览器验收按用户操作顺序完成：

1. 打开创建任务页；
2. 上传材料并填写满分；
3. 生成、检查、编辑并确认百分比评分标准；
4. 进入上传页选择班级；
5. 上传作文、分组并调整页序；
6. 在 OCR Gateway 停止的情况下启动批改；
7. 查看逐篇进度、原图、转写和评分结果；
8. 验证教师确认，以及编辑转写后评分失效；
9. 检查单篇失败不影响其他作文；
10. 恢复最终可预览状态。

完成后启动前端、Grading Gateway 和当前仍保留的 OCR Gateway，并打开创建任务页面供用户继续人工走查；同时证明关闭 OCR Gateway 时 Kimi 主流程仍可运行。

## 完成标准

- 创建任务页只保留已批准的材料、满分和评分标准主流程。
- 评分标准使用百分比权重且合计 100%，必须经教师确认。
- Kimi K3 统一完成材料理解、评分标准生成、作文图片转写和批改。
- 新主流程不依赖 OCR Gateway。
- DeepSeek 环境变量和运行时选择已清除。
- 自动化测试、类型检查、静态检查和构建通过。
- 合成材料的真实 Kimi 和浏览器类人工全流程验证通过，或报告中明确列出尚未通过的外部阻塞。
- 预览服务已启动并打开创建任务页面。
