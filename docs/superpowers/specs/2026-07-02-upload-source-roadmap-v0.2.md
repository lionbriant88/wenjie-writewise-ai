# 上传整理页多来源导入入口占位 v0.2

## Goal

在上传整理页新增一个紧凑的“选择导入方式”区域，提前表达阶段三的多来源导入方向，同时保持当前上传整理、图片分组、OCR mock 和批改队列流程不变。

本轮只做入口占位、路线说明、轻量测试和开发状态文档更新。不接入真实摄像头、扫描仪、希沃视频流、PDF 解析、即时 OCR 或即时 AI 批改。

## Current Baseline

当前产品已经具备：

- 创建任务。
- 上传整理页。
- 本地图片选择上传。
- 添加模拟图片。
- 图片预览、排序、删除。
- 一张一篇、每 2 张一篇、混合页数整理。
- OCR mock 文本草稿。
- OCR 确认后进入批改队列。
- 批改进度页、单篇详情页、班级总览素材池。
- 原卷视图阶段三页面级占位入口。

当前上传页的后续整理流程已经清晰，本轮新增入口必须汇入或指向这个流程，而不是重写流程。

## Non-Goals

本轮不做：

- 不调用手机、平板或电脑摄像头。
- 不调用扫描仪驱动。
- 不接入希沃视频展台真实视频流。
- 不做展台截图。
- 不做真实即时 OCR。
- 不做真实即时 AI 批改。
- 不做 PDF 解析。
- 不做扫描件自动拆页。
- 不做扫描仪硬件控制。
- 不做展台画面到详情页的真实跳转。
- 不新增或修改 `AppStateContext` 字段。
- 不破坏当前本地图片选择、模拟图片、图片整理、OCR mock、批改队列流程。

## Upload Source Types

本轮规格采用以下命名，避免把“已有文件导入”和“现场采集”混淆：

```ts
type UploadSourceType =
  | 'file_import'
  | 'camera_capture'
  | 'scanner_file_import'
  | 'seewo_visualizer_capture'
```

含义：

- `file_import`：用户从当前设备选择已经存在的作文图片或文件。
- `camera_capture`：软件内调用手机、平板或电脑摄像头现场拍摄作文。
- `scanner_file_import`：学校扫描仪或阅卷系统已经生成的图片、PDF 或文件夹导入。它本质上属于已有文件导入的一种学校场景，但教师心智上需要单独入口。
- `seewo_visualizer_capture`：软件内调用希沃视频展台画面进行采集。

## Processing Modes

```ts
type UploadProcessingMode =
  | 'batch_queue'
  | 'instant_review'
```

含义：

- `batch_queue`：进入上传整理页图片列表，经过作文组整理、OCR、批改队列，再进入单篇详情页。
- `instant_review`：采集单篇作文后直接 OCR 和 AI 批改，生成作文与批改结果，并进入单篇详情页。

## Future Capture Persistence Policy

本轮只在文档中预留，不接入代码：

```ts
type CapturePersistencePolicy =
  | 'temporary_only'
  | 'save_to_device'
  | 'ask_every_time'
```

后续拍照采集和希沃展台采集是否保存到设备本地相册/文件系统，需要单独讨论。本轮不决定。

## Upload Entry Area

上传整理页新增“选择导入方式”区域，建议放在当前上传区域位置或其上方，并保留紧凑布局。

标题：

```text
选择导入方式
```

说明：

```text
当前版本支持图片 / 文件导入。拍照采集、扫描件导入和希沃展台采集将在阶段三接入。
```

入口：

1. 图片 / 文件导入
2. 拍照采集
3. 扫描件导入
4. 希沃展台采集

## 图片 / 文件导入

类型：

- `source = file_import`
- `mode = batch_queue`

状态标签：

```text
当前可用
```

说明文案：

```text
从当前设备选择已经存在的作文图片或文件，例如手机相册照片、电脑文件夹图片、扫描仪或阅卷系统导出的图片 / PDF。
```

按钮：

- `选择图片`
- `添加模拟图片`

行为：

- `选择图片` 复用当前文件选择能力。
- `添加模拟图片` 复用当前 mock 图片能力。
- 本轮仍只实际处理图片文件；PDF 和文件夹导入只作为阶段三方向说明，不实现解析。
- 当前上传后的图片继续进入现有图片列表、作文组整理、OCR mock 和批改队列。

## 拍照采集

类型：

- `source = camera_capture`
- `mode = batch_queue`

状态标签：

```text
阶段三接入
```

说明文案：

```text
未来可在软件内调用手机、平板或电脑摄像头现场拍摄作文，预览确认后加入上传整理页图片列表。
```

当前行为：

- 不显示会触发摄像头或文件选择的按钮。
- 只展示阶段三说明。
- 可提示“当前可先通过图片 / 文件导入使用已有照片”，但不要放会混淆来源的“使用本地图片模拟”按钮。

未来路径：

```text
打开软件内拍照界面
→ 拍摄作文
→ 预览确认
→ 加入上传整理页图片列表
→ 作文组整理
→ OCR
→ 批改队列
```

## 希沃展台采集

类型：

- `source = seewo_visualizer_capture`
- `mode = instant_review | batch_queue`

状态标签：

```text
阶段三接入
```

说明文案：

```text
未来可通过希沃白板视频展台采集作文画面，既可用于课堂即时批改，也可用于批量采集上传。
```

希沃展台不是单纯上传方式，而是采集来源。它未来有两条路线。

### 课堂即时批改

类型：

- `source = seewo_visualizer_capture`
- `mode = instant_review`

说明：

```text
展台展示一篇作文后，系统采集当前画面，完成 OCR 与 AI 批改，并直接进入单篇详情页，适合课堂现场讲评。
```

未来路径：

```text
展台画面采集
→ 单篇 OCR
→ AI 批改
→ 生成 essay / gradingResult
→ 直接进入单篇详情页
```

本轮行为：

- 不做真实跳转。
- 不做真实 OCR。
- 不做真实 AI 批改。
- 不做展台画面采集。

### 批量采集上传

类型：

- `source = seewo_visualizer_capture`
- `mode = batch_queue`

说明：

```text
通过展台连续采集多张作文图片，加入上传整理页图片列表，再进入作文组整理、OCR 和批改队列。
```

未来路径：

```text
展台连续采集
→ 上传整理页图片列表
→ 作文组整理
→ OCR
→ 批改队列
→ 单篇详情页
```

本轮行为：

- 不做真实采集。
- 不做真实入队。
- 不做展台截图。

## How Sources Feed Existing Flow

批量处理来源未来统一汇入当前上传整理流程：

```text
批量来源图片
→ 上传图片列表
→ 作文组整理
→ OCR
→ 批改队列
→ 单篇详情页
```

适用来源：

- 图片 / 文件导入
- 拍照采集
- 扫描件导入
- 希沃展台采集的批量采集上传模式

课堂即时批改是例外，它直接生成单篇作文和批改结果后进入单篇详情页，不经过批量整理队列。

## UI Design

入口区域保持紧凑，不抢占上传页首屏：

- 桌面端优先 4 列或 2x2 卡片。
- 移动端单列。
- 每张卡片包含标题、状态标签、2-3 行说明和当前动作/阶段三提示。
- `图片 / 文件导入` 视觉权重最高，显示“当前可用”。
- 其他三个入口视觉更轻，显示“阶段三接入”，避免误以为当前可用。
- `希沃展台采集` 卡片内显示两个小模式条目：`课堂即时批改` 和 `批量采集上传`。

## Acceptance Criteria

- 上传页首屏能看到清晰的多来源入口，但现有整理流程仍是主体验。
- 老师能理解：当前可用的是“图片 / 文件导入”，其他入口是阶段三能力预告。
- “拍照采集”不会被误解为从相册选择已有照片。
- “扫描件导入”被单独展示为学校考试场景，但不承诺当前解析 PDF 或文件夹。
- “希沃展台采集”明确区分课堂即时批改和批量采集上传。
- 本地图片选择、添加模拟图片、分组、排序、删除、OCR mock、确认进入批改队列全部保持可用。
