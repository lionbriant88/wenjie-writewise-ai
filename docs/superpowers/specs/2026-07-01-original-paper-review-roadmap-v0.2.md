# 原卷视图入口与原卷批阅路线占位 v0.2

## 1. Goal

本轮目标是修正 `原卷视图` 的信息架构：它应是单篇作文详情页的页面级 workspace，而不是 `EssaySourcePanel` 内部的一个小 Tab。

页面级 workspace 分为两层：

```ts
type EssayWorkspaceMode = 'grading' | 'paper'
type EssaySourceMode = 'reading' | 'editing'
```

含义：

- `grading`：批改工作台。默认进入，保留当前左侧 OCR 原文和右侧评分诊断、问题批改、全文优化、教师反馈。
- `paper`：原卷视图。整个主体区域切换为卷面批阅画布，用于大尺寸展示学生原卷图片，并在原图左侧、右侧、下方预留未来批注空间。
- `EssaySourcePanel` 内部只保留 `阅读定位 / 编辑 OCR`，不再包含 `原卷视图`。

本轮仍然只做布局修正和阶段三占位，不实现真实图片批注能力。

## 2. Current Baseline

当前单篇作文详情页已经具备以下基础能力：

- 右侧问题卡片点击后，左侧 OCR 原文会高亮对应句子。
- 左侧 OCR 原文中可定位的问题句可以轻量标记并点击，点击后会切到右侧 `问题批改` 工作区并选中对应问题卡片。
- 问题卡片会显示 `已定位 / 未精确定位`。
- OCR 编辑后，定位会重新判断。
- 右侧工作区包含 `评分诊断 / 问题批改 / 全文优化 / 教师反馈`。
- 问题卡片支持语言问题、逻辑问题、加入班级总览。
- 班级总览素材池闭环已经完成。
- 当前已实现的 `原卷视图` 放在左侧 OCR 原文卡片内，导致原卷图片只能显示为小预览，这不符合页面级卷面批阅目标。

因此，本轮要移除左侧小 Tab 中的 `原卷视图`，改为单篇详情页主体区域的页面级切换。

## 3. Non-Goals

本轮明确不做：

- 不接真实 OCR 坐标。
- 不在运行时代码中制造假的图片坐标。
- 不在原卷图片上画问题框。
- 不做图片区域选择。
- 不做手写痕迹。
- 不做拖拽批注。
- 不做自由绘图。
- 不做点击批注定位图片区域。
- 不做点击图片区域选中批注。
- 不做右侧问题卡片定位到图片区域。
- 不新增 AppStateContext 数据结构。
- 不修改上传整理页。
- 不修改批改进度页。
- 不修改班级总览页。
- 不破坏 OCR 原文可点击问题句 v0.1。
- 不破坏班级总览素材池闭环。
- 不把当前占位包装成已经可用的真实原卷批阅。

## 4. 页面级入口说明

单篇作文详情页主体区域上方新增页面级切换：

- `批改工作台`
- `原卷视图`

默认进入 `批改工作台`。

点击 `原卷视图` 后，整个主体区域切换为 `paper` workspace。这个 workspace 不显示评分诊断、总分、AI 置信度、分项评分、全文优化、教师反馈、加入班级总览按钮、OCR 原文 marker 或 OCR 编辑框。

点击 `批改工作台` 或 `返回批改工作台` 后，恢复原有批改工作台布局。

实现约束：

- `workspaceMode` 使用 `EssayResultPage` 本地 state 即可，不新增 AppStateContext 字段。
- `paper` workspace 只作为 `EssayResultPage` 的页面级条件渲染，不为了它大规模重构 `grading` workspace。
- `activeDetailTab`、`activeIssueId`、OCR 原文可点击问题句、加入班级总览、全文优化、教师反馈等现有逻辑保持原状。

## 5. 批改工作台保持现状

`grading` workspace 继续保留当前能力。

左侧：

- 学生作文 OCR 原文。
- OCR 置信度。
- 查看原图。
- `阅读定位 / 编辑 OCR`。
- OCR 原文可点击问题句。
- 右侧问题卡片与左侧原文双向联动。

右侧：

- 评分诊断。
- 问题批改。
- 全文优化。
- 教师反馈。

必须保留：

- 分项评分编辑。
- 总分联动。
- 问题卡片定位。
- 加入班级总览。
- 全文优化稿。
- 本文重点提升点。
- AI 总评。
- 教师补充建议。
- 保存调整。
- 上一篇 / 下一篇。
- 返回批改进度。

## 6. 原卷视图定位

`paper` workspace 是页面级卷面批阅画布。

核心原则：

- 原卷图片是视觉中心。
- 原卷图片必须足够大，方便老师和学生看清原图原文。
- 除顶部导航外，原图左侧、右侧、下方都预留未来批注空间。
- 顶部只承担导航，不承载批注内容。
- 当前只展示原图和批注空间占位，不做真实批注能力。

## 7. 原卷视图顶部导航

顶部只保留必要导航：

- `返回批改工作台`。
- `返回批改进度`。
- 作文编号，例如 `作文 1 · 原卷视图`。
- `上一篇`。
- `下一篇`。

顶部不显示：

- 总分。
- AI 置信度。
- 评分标签。
- 主要扣分项。
- 诊断摘要。
- 分项评分。

## 8. 原卷视图主体布局

推荐使用画布式布局：

```css
paper workspace:
  top toolbar
  main canvas

main canvas:
  grid-template-columns: 220px minmax(520px, 1fr) 280px;
  grid-template-rows: minmax(520px, 1fr) auto;
```

区域：

- 左侧批注预留区。
- 中间原卷大图。
- 右侧批注预留区。
- 底部批注预留区，横跨三列。

布局原则：

- 原图优先，批注区其次。
- 原图使用 `contain` 方式完整显示，不裁切重要内容。
- 原图区域高度建议接近 `70vh` 或更高。
- 页面宽度不足时，左侧批注区可以变窄；右侧批注区和底部批注区继续保留。
- 不要把原图缩成小缩略图。
- 不要使用当前 `EssayPageSorter` 那种小纸张卡片式预览作为主体画布。

## 10. 原图显示要求

如果当前作文有原图：

- 显示原图大预览。
- 如果当前作文有关联原图、上传图片或 imageUrls，必须优先显示真实原图大预览。
- 原图必须是主体视觉中心。
- 尽量保持完整比例。
- 不裁切重要内容。
- 不显示成小缩略图。
- 不继续使用小纸张示意图作为主体画布。
- 不在图片上叠加任何假框、假线、假批注或假坐标。

多页图片：

- 本轮可以只做极轻页码提示，例如 `第 1 / N 页`。
- 如果实现成本低，可以提供原卷页的 `上一页 / 下一页`。
- 不做缩略图列表。
- 不做拖拽排序。
- 不做复杂多页批阅。

如果当前作文没有真实原图：

- 显示大尺寸原卷占位画布。
- 占位画布也要足够大。
- 不要只显示一个小图标。
- 文案：`当前作文暂无原卷图片预览。后续接入 OCR 坐标后，将在此处展示原卷批阅能力。`

## 11. OCR 文本层与原卷图片层的边界

OCR 文本层：

- 数据基础是 OCR 文本字符串。
- 定位依据是问题原句与 OCR 文本的文本匹配。
- 适合展示句子级轻标记、右侧问题卡片选中、定位状态。
- 只属于 `grading` workspace 中的 `阅读定位`。

原卷图片层：

- 数据基础是原卷图片、OCR 坐标块、问题到坐标块的锚点关系。
- 定位依据应是真实 OCR block 或可解释的坐标映射，而不是简单文本命中。
- 适合展示图片区域高亮、批注卡片与图片区域联动、多页卷面切换。
- 当前没有可靠坐标数据，因此只能展示页面级画布和路线占位。

本轮必须保持这两个层次清晰分离。不能因为 OCR 文本能匹配问题句，就在原卷图片上模拟位置。

## 12. mock OCR 坐标结构草案

以下结构仅作为阶段三设计草案，不在本轮运行时代码中新增：

```ts
type OcrPage = {
  id: string
  essayId: string
  pageIndex: number
  imageUrl: string
  imageWidth: number
  imageHeight: number
  blocks: OcrTextBlock[]
}

type OcrTextBlock = {
  id: string
  pageId: string
  text: string
  blockType: 'line' | 'sentence' | 'paragraph'
  bbox: {
    x: number
    y: number
    width: number
    height: number
  }
  confidence?: number
}
```

`bbox` 建议使用 0 到 1 的归一化坐标，避免依赖具体渲染尺寸。图片实际显示时，再根据容器尺寸换算为像素位置。

## 13. issue 到图片锚点的数据结构草案

以下结构也只作为阶段三设计草案：

```ts
type IssueImageAnchor = {
  issueId: string
  essayId: string
  pageId: string
  blockId: string
  anchorType: 'sentence' | 'line' | 'paragraph'
  bbox: {
    x: number
    y: number
    width: number
    height: number
  }
  confidence: 'high' | 'medium' | 'low'
}
```

该结构表达的是“某个问题可以锚定到原卷图片上的哪个文本块”。未来只有当 `confidence` 足够可信时，才应在原卷图片上展示高亮区域。

## 14. 哪些问题能显示在未来原卷批阅里

适合进入未来原卷批阅视图的问题，应同时满足“具体、可定位、不会制造误导”的条件：

- 拼写错误。
- 语法错误。
- 搭配问题。
- 具体句子的表达问题。
- 能明确落到某一句或某一行的逻辑问题。

这些问题需要具备：

- 可匹配到 OCR 文本。
- 可映射到 page/block。
- 有可信 bbox。
- 问题本身足够具体，不依赖全文语境才能解释。

## 15. 哪些问题不能显示在未来原卷批阅里

不适合直接显示在原卷图片上的内容：

- 全文结构建议。
- 整体逻辑诊断。
- 主题偏离判断。
- 笼统表达提升建议。
- AI 总评。
- 教师最终反馈。
- 分数与评分维度。
- 班级总览素材池状态。

这些内容更适合留在批改工作台、全文优化区或班级总览中，不应强行绑定到原卷图片局部区域。

## 16. 原卷批阅视图 v0.1 后续设想

未来真正进入原卷批阅视图 v0.1 时，建议范围仍然保持克制：

- 展示原卷图片。
- 展示可定位问题的批注卡片列表。
- 在图片上显示轻量区域高亮。
- 点击批注卡片后，高亮对应图片区域。
- 点击图片高亮区域后，选中对应批注卡片。
- 支持多页原卷切换。

仍然不建议在第一版加入：

- 手写痕迹。
- 自由绘图。
- 拖拽式复杂批注。
- 导出能力。
- 复杂缩放与画布工具链。

## 17. 阶段三路线

阶段二后段：

- OCR 文本层定位稳定。
- OCR 原文可点击问题句完成。
- 班级总览素材池闭环完成。
- 原卷视图修正为页面级 workspace 占位。

阶段三 A：

- 引入真实 OCR 坐标或可信 mock 坐标。
- 建立 page/block 数据结构。
- 建立 issue 到图片锚点的关系。

阶段三 B：

- 实现原卷批阅视图 v0.1。
- 支持图片区域轻高亮。
- 支持批注卡片与图片区域双向联动。
- 支持多页切换。

阶段三 C：

- 支持教师手动调整定位。
- 支持课堂展示形态。
- 支持导出。
- 扩展更丰富的批阅体验。

## 18. 后续实现前置条件

进入真正原卷批阅能力前，需要先满足：

- 原卷图片数据在作文详情页稳定可用。
- OCR 坐标结构明确，并能覆盖 page/block。
- issue 与 OCR block 的匹配策略明确。
- 坐标置信度策略明确。
- 多页图片的布局与切换方式明确。
- 低置信度或无法定位问题的降级展示方式明确。
- 测试覆盖批改工作台、页面级原卷视图、文本层联动、图片层边界。

在这些前置条件完成前，产品层面只展示页面级 `原卷视图` 入口与阶段三预留画布，不展示任何会让老师误以为图片批阅已经可用的交互。
