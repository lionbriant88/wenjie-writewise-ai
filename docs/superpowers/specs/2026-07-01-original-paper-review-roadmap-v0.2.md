# 原卷视图入口与原卷批阅路线占位 v0.2

## 1. Goal

本轮目标是在单篇作文详情页左侧作文原文区域新增一个轻量入口：`原卷视图`。

当前版本只把路线露出来，不实现真实图片批阅能力。老师可以在 `阅读定位 / 原卷视图 / 编辑 OCR` 三种模式之间切换：

- `阅读定位`：默认模式，继续承载 OCR 原文阅读、问题句轻标记、左右双向联动。
- `原卷视图`：阶段三能力占位，展示原卷图片预览和未来能力说明。
- `编辑 OCR`：继续承载 OCR 文本编辑。

本轮交付的价值是让产品信息架构先容纳“原卷图片层”的未来路线，同时不混淆当前已经稳定的 OCR 文本层能力。

## 2. Current Baseline

当前单篇作文详情页已经具备以下基础能力：

- 右侧问题卡片点击后，左侧 OCR 原文会高亮对应句子。
- 左侧 OCR 原文中可定位的问题句可以轻量标记并点击，点击后会切到右侧 `问题批改` 工作区并选中对应问题卡片。
- 问题卡片会显示 `已定位 / 未精确定位`。
- OCR 编辑后，定位会重新判断。
- 右侧工作区已经包含 `评分诊断 / 问题批改 / 全文优化 / 教师反馈`。
- 问题卡片已经支持语言问题、逻辑问题、加入班级总览。
- 班级总览素材池闭环已经完成，不应被本轮影响。

因此，本轮不重做 OCR 文本层定位链路，只在左侧模式切换中增加 `原卷视图`。

## 3. Non-Goals

本轮明确不做：

- 不接真实 OCR 坐标。
- 不在运行时代码中制造假的图片坐标。
- 不在原卷图片上画问题框。
- 不做图片区域选择。
- 不做手写痕迹。
- 不做拖拽批注。
- 不做自由绘图。
- 不做图片区域点击后联动右侧问题卡片。
- 不做右侧问题卡片点击后联动图片区域。
- 不新增 AppStateContext 数据结构。
- 不修改上传整理页。
- 不修改批改进度页。
- 不修改班级总览页。
- 不破坏 OCR 原文可点击问题句 v0.1。
- 不破坏班级总览素材池闭环。
- 不把当前占位入口包装成已经可用的真实原卷批阅。

## 4. 当前新增的“原卷视图”入口说明

左侧作文原文区域的模式切换从两项扩展为三项：

- `阅读定位`
- `原卷视图`
- `编辑 OCR`

默认仍然进入 `阅读定位`，避免打断老师当前最常用的文本批改路径。

点击 `原卷视图` 后，左侧区域展示：

- 标题：`原卷视图 · 阶段三预留`
- 如果当前作文存在原卷图片，显示原卷图片预览。
- 如果当前作文没有原卷图片，显示空状态：`当前作文暂无原卷图片预览。后续接入 OCR 坐标后，将在此处展示原卷批阅能力。`
- 显示未来能力说明：后续可支持 `卷面定位 / 图片区域高亮 / 批注卡片联动`。
- 显示当前暂不支持清单：图片批注、框选、手写痕迹、拖拽批注、自由绘图、OCR 坐标定位、图片区域与问题卡片的双向联动。

该视图只作为阶段三入口，不展示 OCR 文本层的问题句 marker，不生成任何图片上的问题区域。

## 5. OCR 文本层与原卷图片层的边界

OCR 文本层：

- 数据基础是 OCR 文本字符串。
- 定位依据是问题原句与 OCR 文本的文本匹配。
- 适合展示句子级轻标记、右侧问题卡片选中、定位状态。
- 当前已经完成双向联动。

原卷图片层：

- 数据基础是原卷图片、OCR 坐标块、问题到坐标块的锚点关系。
- 定位依据应是真实 OCR block 或可解释的坐标映射，而不是简单文本命中。
- 适合展示图片区域高亮、批注卡片与图片区域联动、多页卷面切换。
- 当前没有可靠坐标数据，因此只能展示入口和路线说明。

本轮必须保持这两个层次清晰分离。不能因为 OCR 文本能匹配问题句，就在原卷图片上模拟位置。

## 6. 未来“阅读定位 / 原卷视图 / 编辑 OCR”的切换关系

未来单篇作文详情页左侧区域建议稳定为三种模式：

- `阅读定位`：文本阅读与问题句定位，面向快速理解与核对。
- `原卷视图`：原卷图片查看与未来原卷批阅能力，面向卷面核验。
- `编辑 OCR`：OCR 文本修正，面向纠正识别误差。

切换原则：

- `阅读定位` 是默认入口。
- `编辑 OCR` 不显示任何问题句 marker，保持纯编辑体验。
- `原卷视图` 不复用文本 marker，不展示伪造的图片高亮。
- 从 `编辑 OCR` 回到 `阅读定位` 后，文本匹配应基于最新 OCR 文本重新计算。
- 从 `原卷视图` 回到 `阅读定位` 后，现有左右联动应继续可用。

## 7. mock OCR 坐标结构草案

以下结构仅作为阶段三设计草案，不在本轮运行时代码中新增：

```ts
type OcrPage = {
  id: string
  essayId: string
  pageIndex: number
  imageUrl: string
  imageWidth: number
  imageHeight: number
  blocks: OcrTextBlock[]
}

type OcrTextBlock = {
  id: string
  pageId: string
  text: string
  blockType: 'line' | 'sentence' | 'paragraph'
  bbox: {
    x: number
    y: number
    width: number
    height: number
  }
  confidence?: number
}
```

`bbox` 建议使用 0 到 1 的归一化坐标，避免依赖具体渲染尺寸。图片实际显示时，再根据容器尺寸换算为像素位置。

## 8. issue 到图片锚点的数据结构草案

以下结构也只作为阶段三设计草案：

```ts
type IssueImageAnchor = {
  issueId: string
  essayId: string
  pageId: string
  blockId: string
  anchorType: 'sentence' | 'line' | 'paragraph'
  bbox: {
    x: number
    y: number
    width: number
    height: number
  }
  confidence: 'high' | 'medium' | 'low'
}
```

该结构表达的是“某个问题可以锚定到原卷图片上的哪个文本块”。未来只有当 `confidence` 足够可信时，才应在原卷图片上展示高亮区域。

## 9. 哪些问题能显示在未来原卷批阅里

适合进入未来原卷批阅视图的问题，应同时满足“具体、可定位、不会制造误导”的条件：

- 拼写错误。
- 语法错误。
- 搭配问题。
- 具体句子的表达问题。
- 能明确落到某一句或某一行的逻辑问题。

这些问题需要具备：

- 可匹配到 OCR 文本。
- 可映射到 page/block。
- 有可信 bbox。
- 问题本身足够具体，不依赖全文语境才能解释。

## 10. 哪些问题不能显示在未来原卷批阅里

不适合直接显示在原卷图片上的内容：

- 全文结构建议。
- 整体逻辑诊断。
- 主题偏离判断。
- 笼统表达提升建议。
- AI 总评。
- 教师最终反馈。
- 分数与评分维度。
- 班级总览素材池状态。

这些内容更适合留在右侧诊断区、全文优化区或班级总览中，不应强行绑定到原卷图片局部区域。

## 11. 原卷批阅视图 v0.1 后续设想

未来真正进入原卷批阅视图 v0.1 时，建议范围仍然保持克制：

- 展示原卷图片。
- 展示可定位问题的批注卡片列表。
- 在图片上显示轻量区域高亮。
- 点击批注卡片后，高亮对应图片区域。
- 点击图片高亮区域后，选中对应批注卡片。
- 支持多页原卷切换。

仍然不建议在第一版加入：

- 手写痕迹。
- 自由绘图。
- 拖拽式复杂批注。
- 导出能力。
- 复杂缩放与画布工具链。

## 12. 阶段三路线

阶段二后段：

- OCR 文本层定位稳定。
- OCR 原文可点击问题句完成。
- 班级总览素材池闭环完成。
- 新增 `原卷视图` 占位入口。

阶段三 A：

- 引入真实 OCR 坐标或可信 mock 坐标。
- 建立 page/block 数据结构。
- 建立 issue 到图片锚点的关系。

阶段三 B：

- 实现原卷批阅视图 v0.1。
- 支持图片区域轻高亮。
- 支持批注卡片与图片区域双向联动。
- 支持多页切换。

阶段三 C：

- 支持教师手动调整定位。
- 支持课堂展示形态。
- 支持导出。
- 扩展更丰富的批阅体验。

## 13. 当前占位视图不实现的能力清单

`原卷视图` 占位页必须让老师清楚知道当前尚未支持：

- 图片批注。
- 框选。
- 手写痕迹。
- 拖拽批注。
- 自由绘图。
- OCR 坐标定位。
- 右侧问题卡片定位到图片区域。
- 图片区域定位到右侧问题卡片。
- 多页原卷批阅工作台。
- 导出带批注原卷。

这些能力只作为后续路线，不进入本轮实现。

## 14. 后续实现前置条件

进入真正原卷批阅能力前，需要先满足：

- 原卷图片数据在作文详情页稳定可用。
- OCR 坐标结构明确，并能覆盖 page/block。
- issue 与 OCR block 的匹配策略明确。
- 坐标置信度策略明确。
- 多页图片的布局与切换方式明确。
- 低置信度或无法定位问题的降级展示方式明确。
- 测试覆盖文本层联动、图片层入口、未来图片锚点数据的边界。

在这些前置条件完成前，产品层面只展示 `原卷视图` 入口与阶段三预留说明，不展示任何会让老师误以为图片批阅已经可用的交互。
