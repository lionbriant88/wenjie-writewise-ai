# 教师云端 MVP 接通方案

状态：用户于 2026-09-27 回复“确认”，已批准本设计。实施计划另列，本文不是已实施或已发布记录。

## 目标与现状

用户要求把现有教师页面接到已上线的 DeepSeek 后端，先做小范围 MVP 测试。验收目标是：登录 → 创建任务 → 按学生上传作文 → 一键启动批改 → 教师查看、修改、确认 → 刷新或重新登录后仍能查看原图、结果和修改。

部署源为 `.worktrees/codex-teacher-pilot-accounts`。当前生产代码为 `65a3f22`，本地 `aa1504c` 仅补充验收记录。DeepSeek 官方接口已完成一次公网合成图片验证，但生产 `AccountApp` 只渲染账号页；现有完整业务页面位于 `LocalDemoApp`，`AppStateProvider` 以演示数据和内存状态运行。不能直接打开这一路由并声称支持保存。

本次沿用 30 教师 + 1 账号管理员、固定密码且禁止修改、Vercel + Supabase、官方 `deepseek-flash`、单篇一次多模态识别/评分/反馈、教师复核和现有 v2 合同。没有 OCR、自动模型回退或多学生合并请求。

## 方案选择

推荐复用现有页面，以 Supabase PostgreSQL 保存业务记录、同一 Supabase 项目的私有 Storage 保存原图，以 Vercel Queues 唤醒后台执行。数据库负责最终的归属、版本、幂等和全站并发约束；消息队列只携带不可预测的作业 ID。

对比方案：

| 方案 | 优点 | 对本次目标的影响 |
| --- | --- | --- |
| 私有 Storage + PostgreSQL + Vercel Queues（推荐） | 复用已有云项目，页面关闭后仍可处理，原图绕开函数上传体积限制 | 新增业务表、私有存储配置和队列适配，需要完整故障测试 |
| 浏览器缓存 + 当前同步接口 | 开发量较小 | 换设备和重新登录不能可靠恢复，页面关闭后无法完成整班队列，不满足目标 |
| 独立常驻服务器和 worker | 后台运行可控 | 需要新增运维和部署体系，超出这次 Vercel MVP 接通范围 |

Vercel 官方文档列出 Hobby 包含队列操作额度，队列消费者可通过私有触发器运行；仍须核实当前项目实际可用性。本阶段不升级套餐、不订阅其他服务；若项目不支持，保持账号站点可用，报告具体阻塞，不静默改换架构。[队列用法](https://vercel.com/docs/queues/quickstart)、[价格与限制](https://vercel.com/docs/queues/pricing)

## 教师使用流程

1. 教师登录后进入自己的任务列表，首次为空；账号管理员仍进入账号管理。退出、会话失效或切换账号立即卸载教师数据并丢弃迟到回调。
2. 复用现有单页创建流程：原题材料选填、默认 40/40/15/5 维度可编辑、AI 辅助可选，最终创建按钮确认评分标准。服务器校验并保存当前确认版本后再进入上传页。保存失败保留表单并提示，不能假报成功。
3. 复用学生卡片：默认“学生1”“学生2”，每人多页图片/PDF 转换页/拍照。原图上传成功并经服务端验证后才进入待批改。上传失败只影响该学生或页面，已上传内容可恢复。
4. 一次启动任务全部待批改作文。排队在服务器保存，页面仅显示和轮询状态；刷新、退出或关闭页面不撤销已启动作业。单篇明确失败不阻断其他作文。
5. 结果页复用现有识别正文、分数、问题、改写、原卷和教师复核控件。教师修改与确认由服务端记录版本；修改识别正文后旧结果失效，显式重批使用确认文本、零图片。
6. 每次成功保存后显示“已保存”；保存中、失败和版本冲突有明确反馈。不同标签页修改同一版本时返回冲突并重新加载，不能静默覆盖。

## 数据与权限

业务数据继续保存在现有新加坡 Supabase 项目 `wudbhdyqgnbnuorebhnu`。新增不暴露给 Data API 的业务 schema，独立于 `pilot_auth`；不得重建账号、修改密码或扩大账号表写权限。

最小实体为任务草稿/确认评分标准、学生作文/有序页面、上传登记、批改作业/执行记录、规范化 AI 结果、教师修订与确认、队列投递 outbox、共享 Provider 准入。每条业务记录绑定服务端会话确定的教师 ID，所有关系用教师 ID 复合约束；所有查询与更新都检查归属。管理员角色不自动取得教师作文读取权。猜中他人任务、页面、结果或作业 ID 仍返回 404。

前端发送业务命令与预期版本，不能自报 owner、已完成状态或可信 AI 结果。评分、任务计数和当前有效结果由后端生成。新增表的运行角色仅得到必需权限；迁移采用已有管理连接，运行时不得自动迁移。

图片放入私有 bucket，不创建公共读取策略。服务端验证归属后签发仅针对当前随机对象路径的上传凭证；客户端不取得服务级 Secret。上传完成后验证类型、实际字节数和摘要，固定不可覆盖的版本；worker 在调用模型前再次核对摘要，避免签名上传重放篡改。读取原图时也先验证归属，再提供短时读取地址；已签发地址失效前的可访问窗口须在部署说明中明确。[Supabase 签名上传](https://supabase.com/docs/reference/javascript/file-buckets-createsigneduploadurl)

原图不做未经质量验证的有损压缩。PDF 转图片和 DOCX 提取正文保留现有处理；请求和文件上限复用现有验证常量，并在前后端一致呈现。新 CSP 只增加该 Supabase 项目的必要上传/图片域名，不放宽到任意域名。

需要的新增服务端配置为该 Supabase 项目的 URL、私有 bucket 名和存储服务凭据。凭据保存在 ignored 本地配置及获授权的 Vercel Secret，禁止聊天粘贴、回显、普通日志或 VITE 变量。申请云端凭据保存授权时应列出实际 Secret 名称和目标项目；已有 DeepSeek 密钥不重建。

## 批改与可靠执行

队列只唤醒作业。作业输入从数据库读取固定评分标准版本、作文版本及按顺序的私有页面；不采用浏览器提供的任意下载 URL。内部继续构造 `multimodal-grading-request-v2`，复用现有严格校验、Prompt、Provider 和 `grading-result-v2` 归一化服务。

`POST /grading/grade-images` 的既有 Gateway 合同保留；生产业务适配必须经过同一持久执行边界，不能留下可绕开账号归属、共享准入和结果保存的付费直通入口。业务命令 API 与 Gateway 合同分层，不恢复旧文本入口。

每个作文版本与评分标准版本只有一个正常初次执行身份。事务保存作业和 outbox 后才投递；投递失败可以重投同一个作业 ID，重复消息不得再次调用模型。outbox 有有界恢复扫描，页面读取可触发安全补投；队列消息过期不能丢失数据库中的待处理记录。

本轮所有 Provider 阶段共享数据库硬上限 1，包括材料理解和评分标准生成，不能只限制逐篇批改。数据库事务占位后才能连出；队列自身并发设置只作为附加保护。成功结果必须先持久化再完成消息。数据库成功而消息确认失败时，重投只读取已完成结果。

使用执行随机令牌、版本栅栏和状态比较更新。工作进程消失、超时或网络结果未知，记录 `result_unknown` 并保留并发占位；心跳/时间到期不能当作“未调用”证据。迟到结果只允许对应原令牌提交。只有能证明未发出或明确结束的调用才释放占位，沿用既有 `EACCES + connect` 严格判定，Abort/超时优先。前端“检查结果”只查询同一执行，不创建新请求。

明确鉴权/余额/配置错误暂停队列；明确 429 退避并限制重排次数，不可重试错误停在单篇。消息基础设施自动重投与模型重试分离，任何未知调用不得因为消息重投再次 completion。恢复流程不得加入匿名解锁或按 TTL 强行释放未知槽位。

Vercel consumer 最长运行时间沿用 300 秒，Provider 截止沿用当前受控配置并留出写库时间。长任务拆为逐篇持久作业，不能把全班压进一个 300 秒函数。进度状态持久保存，教师再次登录读取当前状态。

## MVP 边界与数据管理

本轮先用于项目所有者和少量受邀教师的合成/自编测试作文。真实学生材料仍需明确处理授权、保存期限和删除政策后再使用；“无费用限制”不替代这些决定。

测试记录默认保留至教师主动删除，不新增未批准的自动清空期限。删除是显式操作：先隐藏并阻止新调用，再安全清理对象和业务结果；正在处理或结果未知的作业保留最小执行墓碑，防止删除后重投重复计费。界面明确删除范围。未提交的临时上传在 24 小时后进入后台清理，已关联到任务的原图不自动删除。

当前本地班级 AI 总结使用 fake client，不能随教师入口一起上线。现有逐篇结果是本轮交付范围；云端页面不暴露会调用 fake 总结的按钮，后续班级总结须另行实现和验收。手机浏览器页面需要检查，文件输入自动化不能代替真机摄像头验收。

## 文件与模块边界

- `platform-api/src/pilot/`：业务合同、归属查询、版本写入、上传登记、对象存储适配、作业与共享准入、队列投递/消费；保持小模块，不把所有逻辑写入当前 `server.ts`。
- `platform-api/src/migrations/002_pilot_grading.sql`：新增业务 schema 与最小权限；新增迁移命令与回滚检查，不修改已初始化账号。
- `grading-gateway/src/`：提取可复用的 v2 执行服务，原 HTTP 路由和云端 worker 共享归一化/错误处理，避免第二套评分逻辑。
- `api/` 和 `vercel.json`：私有队列入口、函数时限、明确路由和限定 CSP。
- `app/src/pilot/`：已认证教师入口、云端业务客户端和状态适配；不把 mock 初始化状态导入生产。
- 现有 `CreateTaskPage`、`UploadPage`、`ProgressPage`、`EssayResultPage`：复用外观和业务组件，将命令成功与云端保存绑定，处理加载/失败/冲突；本地 demo 保留显式开发模式。

## 验收与发布门槛

先完成 fake Provider + PGlite/数据库真实事务测试：账号 A 不能读写 B 的任务/图片/结果；两次提交、两个 worker 和两个实例竞争仅调用一次；保存结果后故障重投不调用；未知结果占位不释放；旧版本结果/迟到结果不能覆盖；原图重放篡改被拒绝；未完成上传不能批改；教师修订与确认经刷新恢复；队列关闭页面仍可推进；退出和换号没有残留数据。

检查现有账号安全、Gateway v2、创建任务和上传流程的回归、两端类型检查、lint 与生产构建。只有本地验证通过，才进行云数据库迁移、私有存储/Secret 配置和生产部署；缺少依赖时保持原账号入口或明确未配置状态。

公网最终用合成材料验收一条手动评分标准单图流程、一次多页流程和可选 AI 评分标准流程；每种用例独立一次性记录，不盲目重试，记录实际调用数和安全用量摘要。验证刷新、退出重登、教师修改确认、第二账号隔离及队列重投保护。测试通过后才能称“教师网页 MVP 接通”；不能据此声称 30×50 吞吐或真实教学质量通过。
